---
description: "初始化闪电写手工作环境，可直接使用完整思路或通过对话梳理思路。"
---

调用 flash-writer 技能，但不要直接生成正文。按以下步骤执行：

---

## 第零步：先判断用户意图

- 用户已经附上或明确指定写作思路文件时，自动使用该文件并以其所在目录作为写作项目；不要再询问目录、入口或再次索要文件。初始化个人写作档案后，直接执行第三步 A。
- 用户只说“直接开写”但当前上下文没有可识别的思路文件时，只询问一次文件；拿到后再以文件所在目录作为写作项目，初始化个人写作档案并执行第三步 A。
- 用户明确说“一起梳理”时，不再询问入口，按第一步确认项目目录后直接执行第三步 B。
- 只有裸命令且无法判断意图时，才在准备文件后展示两个入口供用户选择。

---

## 第一步：介绍 + 询问目录

先向用户输出以下内容（原样输出），然后等待用户回复：

```
闪电写手 ⚡ 已启动

你可以直接提供完整的写作思路，也可以先说一个大致想法，由我通过对话帮你梳理。两种入口使用相同的正式写作流程和质量标准。

我会在你的项目中创建或复用唯一的 `references/` 文件夹，准备写作模板和参考案例。

默认放在项目根目录，你也可以指定其他目录。直接回车用默认位置，或输入路径：
```

等待用户回复。用户回车或不指定路径，则用项目根目录；用户指定路径则用指定路径。

---

## 第二步：创建文件 + 选择入口

用户项目始终只使用一个 `references/` 目录：

- 使用本技能目录中的 `scripts/project_setup.py --project-dir <用户选择的目录>` 准备文件。它会检查 `writing-template.md`、`real-example.md` 和 `screenshot-guide.md`，只复制缺失文件；属于 Flash Writer 的同名文件保留原文件，绝不覆盖，也不创建第二个目录。
- 如果返回 `reference_conflict`，不要继续初始化，也不要把冲突文件当作本技能模板。告知用户冲突的实际路径，请用户选择其他项目目录或自行处理该文件；处理后重新运行。

使用本技能目录中的 `scripts/profile_store.py init --project-dir <用户选择的目录>` 初始化个性化写作档案。该命令只创建缺失文件，不覆盖已有档案；项目状态保存在当前用户的 `~/.flash-writer/projects/`，不会在用户选择的目录中创建 `.flash-writer/`。不要把个人规则写入 Skill 本体。

文件准备完成后，依据脚本返回的 `created` 或 `preserved` 向用户输出以下内容；每个文件根据实际情况标注“已创建”或“已保留”：

```
已准备 `references/`：

- [writing-template.md](<实际绝对路径>) — 已创建/已保留，填写写作思路
- [real-example.md](<实际绝对路径>) — 已创建/已保留，完整案例
- [screenshot-guide.md](<实际绝对路径>) — 已创建/已保留，图片截图指南

同时已启用个人写作档案。后续写作中确认沉淀的可复用经验会自动延续，不需要在下一篇重复说明。

写作风格留空时会自动使用 Flash Writer 内置默认风格；你也可以直接描述自己的风格，或提供自己写过的文章作为样本。

请选择一种开始方式：

- **直接开写**：我已经准备好完整的写作思路，确认后按既定流程开始写作。
- **一起梳理**：我先说大致想法，AI 帮我逐步整理成完整的写作思路，确认后再开始写作。
```

注意：把每个 `<实际绝对路径>` 替换成用户所选目录下对应文件的绝对路径；路径包含空格时用尖括号包裹链接目标。文件名使用 markdown 链接格式，让用户可以直接点击打开。不要输出不存在的动态目录名。

不要默认替用户选择。等待用户选择入口；用户已经在调用命令时明确入口，则直接执行对应流程。

---

## 第三步 A：直接开写

用户选择“直接开写”后：

1. 使用用户已经附上、指向或在当前上下文明确指定的写作思路文件，不再次索要。只有用户仅说“直接开写”但当前上下文确实没有可识别的思路文件时，才请其提供一次；如果用户要使用刚准备的模板，给出可点击的实际绝对路径。
2. 完整读取写作思路，只检查五个核心部分：
   - **原则与边界**：是否明确内容类型、必须遵守的范围和关键禁用项
   - **受众**：是否明确目标读者和认知水平
   - **目标**：是否用具体场景描述预期效果，而非抽象的“了解 X”
   - **核心观点**：是否有作者真正想表达的判断
   - **写作思路**：是否有章节级结构和关键 `》` 指令
3. 检查前后矛盾、事实与推断混淆、第一人称经历归属不清等高返工风险。真实案例与事实、内容参考按文章需要检查；风格、格式和图片没有特殊要求时允许留空。
4. 已经明确的信息不要重复问。只有关键缺失、矛盾或事实边界问题才请用户补充；没有问题就尽快进入 SKILL.md 的第一步“对齐信息”，然后推荐大纲。

---

## 第三步 B：一起梳理

用户选择“一起梳理”后，先问一个开放问题并等待回答：

```
先不用整理，你可以像聊天一样告诉我：你想写什么，为什么最近想写这个，以及你目前最确定的判断是什么。
```

收到回答后：

1. 先复述已知信息和写作模板中的关键缺口，不立即发出整份问题清单。
2. 优先确认受众、核心观点、目标；再按需确认真实案例与事实、参考资料、必须包含和禁止事项。
3. 根据答案推荐高层论证路径或章节骨架，请用户判断；不要要求用户从零填写章节目录，也不要在这里展开章节任务、证据和资料用途。
4. 最后只在确有特殊要求时补问写作风格、格式偏好和图片素材。
5. 通常每轮最多问 2 个问题，特殊情况下最多 3 个。问题必须对应模板缺口；不问也不会增加整篇返工风险的内容不要问。
6. 用户说“不知道”时，给出有理由的建议，明确标为 AI 建议并请用户确认，不得把建议悄悄写成作者观点或事实。

当受众、核心观点、目标、支撑材料或推理、高层论证路径或章节骨架、必须与禁止边界都已明确，且没有高返工风险时停止追问。标题、精确字数、章节数量、Emoji 和一般格式偏好不阻塞。

整理前严格读取 `references/writing-template.md`，按同一结构写入用户目录下的完整 `writing-template.md`，保留模板中的 `》` 指令机制以及全部 10 个二级标题原名：原则与边界、受众、目标、核心观点、真实案例与事实、写作思路、写作风格、格式偏好、内容参考、图片素材。把高层论证路径或章节骨架写进“写作思路”，不得另造“高层写作骨架”等栏目；不得合并“写作风格”和“格式偏好”。没有内容的按需或选填部分也保留标题，并填写“暂无”或“无特殊要求”，不能省略。

AI 补充而用户尚未确认的内容统一标记为 `【AI 建议，待确认】`；不确定的事实在“真实案例与事实”表格的性质或备注中标为“待核实”。向用户展示或链接整理后的文件，请其重点确认核心观点、真实案例、高层骨架和禁止事项。用户最终确认后移除临时 AI 建议标记；这份完整模板成为干净的权威输入。

随后仍须完成 SKILL.md 第一步中的信息准备：加载个人档案和项目上下文，完整读取最终写作思路，按需读取约束文档、参考资料、风格样本和 URL。向用户展示读取摘要，但不再无条件询问“有遗漏或理解错误吗？”；只有这些读取发现新的冲突或关键缺失时才追问。梳理阶段已经确认的风格特征不再问，只有新提取且尚未确认的特征才确认。完成后进入第二步“推荐大纲”，将已确认的高层骨架细化为包含章节任务、证据、案例和资料用途的 2-3 级可写大纲，不重新争论已确认骨架。

---

## 第四步：共同校验规则

两个入口最终都必须得到同一结构的完整写作思路，并进入同一套正式写作流程。校验通过时输出：

```
写作思路校验通过，没有缺失或矛盾。进入大纲设计。
```

“直接开写”从第一步“对齐信息”进入。“一起梳理”确认后仍完成第一步的资料准备，但不重复询问已确认信息；随后从第二步“推荐大纲”进入。

内置默认风格保存在 Skill 的 `references/built-in-style.md` 中，由工作流按需读取；不要复制到用户项目，也不要覆盖用户提供的风格文件。
